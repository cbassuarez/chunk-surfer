# Chunk Surfer — three menu VFD systems

Design review dated November 16, 2026, America/Denver. Recommendation: **Night ledger**. Production sources have not been changed by this study. The repository already contained unrelated changes when work began; those were preserved.

**Start with what the menu actually does.** The authority is [title-menu.js](/home/seb/chunk-surfer/src/game/title-menu.js), [title.js](/home/seb/chunk-surfer/src/game/title.js), [save.js](/home/seb/chunk-surfer/src/game/save.js), and the destinations each callback opens. These distinctions precede the images.

| Explicit label | Actual action and availability | Required message; misleading reading to prevent |
|---|---|---|
| New game | Always available. Calls `requestFrontEndNewRun`, eventually `newGame({prepareInVan:true})`. With an active run it first arms `START NEW RUN? PRESS ENTER AGAIN`. Replacing the active night preserves settings and durable profile history; the new shift is prepared in the van. | A fresh night from its origin. A play triangle conflates this with Continue; a power button suggests launching the app; a trash can suggests deleting the profile. |
| Continue | Present only when `getSave().run.status === 'active'`, including an authoritative in-memory run when persistent storage is unavailable. Calls `requestFrontEndContinue`, retaining run identity, checkpoint and saved state. The existing microphone decision and scene handoff may still intervene. | Resume this night, with its history intact. Never imply a new night, a chapter picker, an exact visible progress percentage, or instant completion of world loading. |
| Archive | Present with an active run or any qualifying run, ending, achievement, or knowledge history. Opens the achievement/discovery/filed-return archive. Filed returns can include playable archived recordings. | Persistent profile records across nights. It is broader than an audio library; a tape reel alone is inaccurate. |
| Endings | Present after at least one ending has been seen. Opens the outcome index, reached/unreached information and contextual hints/dossiers. | Review outcomes. A trophy overstates success; branching imagery must not imply that selecting this menu item chooses or replays an ending. |
| Field replays | Present after an ending or at least one filed knowledge document. Opens a room with **SCENES**, **MEDIA ARCHIVE**, and **LEAVE**. Scenes are playable field visits; media are retained source clips. These visits do not alter the active night. | Revisit scenes **and** play source media. A film-only screen, an audio reel, or a rewind of the active run would all be incomplete or wrong. |
| Settings | Always available. Opens the out-of-game settings surface. | Audio, display, controls and accessibility. An equalizer implies only audio; moving a slider during hover falsely implies changing a value. |
| About | Always available. Opens credits/game information. | Information and authorship. It is not another archive of in-world discoveries. |
| Quit | Present only when the desktop Quit callback exists. | Close Chunk Surfer. Do not imply erasing a night or switching off the fictional recorder. |

First visit on desktop therefore has **New game, Settings, About, Quit**. An active night adds **Continue** and **Archive**. A profile with filed returns can show all eight. With historical progress but no active night, Continue disappears. A documents-only history can expose Field replays while Endings remains absent. The review includes all five fixtures and a browser/desktop Quit toggle in the design controls.

There is a deliberately authored exception in [six-loop.js](/home/seb/chunk-surfer/src/game/six-loop.js): during its special session both launch routes can rejoin the same night. The visual redesign must keep the existing callbacks and must not advertise that narrative exception in the menu or reset its state. Availability is never inferred from a fabricated save-slot count.

**Primary hardware evidence.** The following sources were inspected; they support construction choices, not player comprehension. No reference photograph or model render was converted into artwork.

| Evidence | Direct observation or documented behavior | Consequence for this menu |
|---|---|---|
| [Noritake custom glass guidance](https://www.noritake-elec.com/support/design-resources/custom-design/custom-vfd-glass), construction figures and pattern rules | Separate anode/phosphor, grid, filament and cover-glass layers; custom phosphor shapes; minimum printed widths of 0.18 mm for standard green and 0.20 mm for other colors. | Keep emission beneath the existing glass. Give every luminous feature a stable physical footprint and real clearance. These millimeter limits cannot be converted to CSS pixels without a physical scale for the fictional instrument. |
| [Noritake custom pattern photograph](https://www.noritake-elec.com/wp/wp-content/themes/noritakeelec/inc/part/operation/img/p_cus.jpg) | Segments, bars, symbols and special shapes share a designed panel; many shapes are not ordinary rectangular pixels. | Different physical cell constructions are credible. Arbitrarily overlapping custom silhouettes are not solved by adding glow. |
| [Newhaven D0107LT-33-0701A ON/OFF photographs](https://newhavendisplay.com/7-segment-7x1-vfd-glass-3-3vac-green-display/) | The powered image shows selected green digits; the explicitly labeled powered-off image retains pale segment patterns and visible internal structure. | Unlit material reflects ambient light. It is not a low-brightness emitted duplicate. The preview separates these passes. |
| [Noritake operation/timing guidance](https://www.noritake-elec.com/technology/general-technical-information/vfd-operation) | Multiplex cycles should be fast enough to appear steady; the guide describes scanning above 100 cycles/s and inter-digit blanking on the order of 10–50 μs to suppress ghosting. | No decorative visible scan line, compulsory flicker, or long luminous trail. The slower selection sequences below are authored firmware-like behavior, not phosphor decay. |
| [Noritake recorded LCD/VFD comparison](https://www.noritake-elec.com/support/videos/video?id=TYrWAGQHBc4) | Viewed the recorded changing equalizer patterns, including views around 11 s and 17 s. Addressed bars change while the text remains legible. No persistent drawn trail was apparent at the recording's resolution. | Use clean address changes and retain a readable context. This ordinary-speed recording cannot establish microsecond response, precise decay constants, calibrated brightness or absence of camera artifacts. |
| [Newhaven D0420SD-42-2001FN specification/drawings](https://newhavendisplay.com/content/specs/D0420SD-42-2001FN.pdf) | Documents a 5×7 character matrix, character dimensions and a dynamic drive scheme. | Reuse the game's existing 5×7 glyph ROM. The proposed graphic matrices are design constructions, not claims that this specific module fits the game's case. |

The manufacturer pages establish electrodes, patterning, drive and examples. Color choices, duty ratios, the application-specific art and 420–600 ms sequences are **artistic interpretation**. No hardware fabrication, electrical simulation, calibrated luminance, lifetime test, or manufacturer approval is claimed.

**A grammar before alternatives.** A label remains the authoritative action. A picture supplies a state relationship: blank origin versus retained state; stored records versus indexed outcomes versus revisitable content. Static context uses dimmer emission; the selected destination/marker uses the brightest tier. A moving highlight never stands in for the real program meter in the bezel.

All text uses the existing uppercase 5×7 ROM; it is never stretched into a 7- or 14-segment approximation. Character advance is six dot pitches. Menu labels use pitch 1.8 px, 12.6 px cap height and a reserved 13-character field. At rest, selected labels are duty 1; other labels are approximately 0.66 before quantization. The action sentence is 0.92, the secondary consequence 0.75. Duties are quantized to 1/16. Color alone does not identify selection: the systems have a physical cursor, inverse cells or corner brackets respectively.

The canonical review case is **680×572 CSS px** including the transparent crop margin. Its real bezel is 78×28 UI cells at cell metrics **8.45×20 px**. The aperture is **635.44×466 px**, at `(22.03,53)` within the crop. The content budget ends before the existing footer. At both 1280×760 and 1280×800 with UI 100%, the case has the same internal dimensions; only its screen origin changes.

The left action field begins at x=68. Its hit region starts x=51, width=211. The right graphic is **320×256 px**, approximately 53% of the usable display width, with a separate caption bank below. No glow or graph can occupy the bezel, wordmark, source, meter or printed key legends. The preview keeps a 24–38 px optical gap between labels and the right graphic.

**Three complete systems.** Each uses purpose-authored binary geometry. The first and third are fixed custom cell banks: they do not swap overlapping “custom icons” or morph physical phosphor. The second is a full graphic matrix. Captions and labels have separate, fixed character banks.

| System | Composition and physical cell construction | Selection and motion |
|---|---|---|
| Path register | One horizontal title at `(54,85)`, a profile-state line, action rows from y=165 at 32 px pitch. Right picture at `(300,157)`. Orthogonal 16×13 node lattice: 208 pads of 6×6 px plus 387 horizontal/vertical bridges of 10×3 or 3×10 px, 20 px pitch. **595 non-overlapping anodes**. Amber `#ffcf74`. | A 5×17 px cursor with two 29×2 px locating strokes. Address groups follow the path or category tracks; settle by **480 ms**. The extension keeps the distinctions established by the proof. Archive uses a bank of records (the ledger spells out WORK, FINDS, RETURNS). Endings uses terminal nodes with filled/unfilled caps and the caption OUTCOME INDEX. Field replays combines a walkable doorway and a separate media window, connected by a return path; the caption and copy explicitly name both. About is a credits/information document. Quit is an arrow crossing the application boundary. None uses a trophy, “all complete” count, fake waveform, or invented save percentage.

**Rendering and timing contract.** The executable reference is [renderer.js](/home/seb/chunk-surfer/output/vfd-menu-systems/renderer.js). Its local matrices are authored with flat strokes/rectangles and binary sampling into physical cells. There are no source models, photographs, grayscale-to-dot conversion, stochastic dithering, gradients in the phosphor, or sampled surface shading.

The paint order is the existing plate/well, neutral dormant material, addressed emission, two copies of that same emission for optical spread, then the existing cover-glass pass. Dormant material is `#66735c` at ambient alpha 0.04 in the final view; the dedicated unlit inspection raises it to 0.38 to reveal the construction. The mask inspection is diagnostic, intentionally much brighter than a real off-state. It is not a proposed powered state.

Emission has a crisp core. Its two halo copies use blur radii **2.1 px at alpha 0.23** and **5 px at alpha 0.08**. No halo has an independent shape, displaced ghost, or history buffer. Scale those radii with display geometry, and rasterize at the actual output DPR. Keep the optical material pass separate from the luminous mask so labels and mechanics never acquire light.

The picture is recognizable on frame zero: cells waiting for their address group receive 22% of their intended duty. The final group address is calculated from the stored onset multiplied by **2.2 / 2.7 / 4.4** for Path/Ledger/Relay and compared with normalized entry time. Settings also sequences four stationary category groups. The preview samples the authored clock every **20 ms** using `requestAnimationFrame`; this is application animation, not the VFD multiplex refresh. Once the target duration is reached, the clock is discarded and the resting image stays unchanged. There is no idle loop.

Frame contact sheets have rows New game, Continue, Settings, and columns **0, 80, 180, 360, 600 ms**: [Path register](/home/seb/chunk-surfer/output/vfd-menu-systems/0-frames.png), [Night ledger](/home/seb/chunk-surfer/output/vfd-menu-systems/1-frames.png), [Relay atlas](/home/seb/chunk-surfer/output/vfd-menu-systems/2-frames.png). Interactive inspection has 20 ms scrubbing, final/raw/fixed-mask/unlit views, 1:1 case inspection and a 2× graphic crop. Narrow previews report the actual displayed scale and provide readable external action controls.

Every changed selection commits the label, caption and input target immediately. There is only one target picture; old geometry never crossfades over a new action. Navigation events less than **100 ms** apart snap the latest target to rest. Reselecting the same item does not restart its sequence. The review-only Replay control is for inspection and is not proposed as a game action. Enter, Space and pointer activation never wait for art completion. New game's existing second confirmation is the only deliberate additional activation step. Navigation disarms it; held activation repeat is ignored.

Reduced Motion, including the OS preference, presents the final state immediately, with steady selection and no sequence. Hiding the page snaps pending pictures to rest; returning does not replay elapsed animation. Changing carousel alternatives does not start an animation. Audio stays behind the game's existing audio gate and the bezel's real program meter stays connected to its existing source. Preview activation only reports the production route and does not mutate a game save or launch those destinations.

**Integration boundary.** Keep `withMachinePanel`, the frame calculation, glass, footer, meter, background renderer, front-end session, input/audio ownership and action callbacks. Replace only the content callback's layout/art drawing. Pass the selected action ID, profile flags, confirmation state and Reduced Motion into the new renderer. The labels and hit regions must come from `titleMenuItems`, with the current keyboard/controller/pointer handlers retained. Convert review pixel coordinates to UI-cell coordinates using the measured cell metrics; emit through `uiDraw` inside the existing aperture clip, before the native glass callback. No production import of this review directory is needed or proposed.

For other UI sizes, anchor to the **actual unchanged aperture** rather than changing the bezel. Reserve the left field for the 13-character label, keep a gap of at least 24 output CSS px, fit the right matrix uniformly, and preserve its cell aspect ratio. Keep cap height at least 11 output px; at UI 100% it is 12.6 px. If the selected row does not fit, retain the existing scroll/start logic and navigation arrows instead of hiding an action or shrinking labels below that floor. A compact interior can collapse the profile-state line and reduce title padding before sacrificing a row. The preview proves the canonical size, not every production UI-scale preset; integration must still inspect the 80–150% presets and smallest supported 960×600 stage. This is an explicit remaining acceptance check, not a claimed completed game-wide test.

**Hardware credibility and comprehension are separate judgments.**

| System | Hardware credibility, based on evidence | Action comprehension, author judgment only |
|---|---|---|
| Path register | Stable, non-overlapping custom anodes and clear segmentation fit the documented patterning model. Address count and routing are not a manufacturable electrical design. | Fresh origin versus saved point is coherent, but may be read as chapter selection. |
| Night ledger | Matrix glyphs and addressed graphic cells are directly supported by real VFD examples. The proposed 120×104 bank and title/text banks are a fictional module layout. | Best current candidate: blank versus retained/marked sheet is directly visible, and the three history destinations have different structures. A document may still imply Save/Load. |
| Relay atlas | Fixed bar cells are physically coherent with custom patterning; no particular manufacturer module or diagonal sequence is claimed. | Most uncertain: the carrier could imply inserting a storage cartridge. Labels and action copy are necessary. |

There were **zero unfamiliar-player sessions**. No comprehension percentage, preference ranking, task time or player quotation is reported. The recommendation favors Night ledger for its explicit retained-state contrast and its match to the game's filed-work language, balanced against the strongest commercial matrix precedent. It does not claim empirical superiority.

**Runnable interpretation test.** Run `python3 /home/seb/chunk-surfer/output/vfd-menu-systems/serve.py`, then open [the isolated test](http://127.0.0.1:5497/test). The same test is available under the interactive preview. It has 18 randomized picture trials (six actions × three systems), followed by six labeled-menu tasks covering resume, restart, archive, ending hints, field replay and accessibility. The title-menu labels and captions are hidden during picture trials; words drawn as intrinsic artwork remain. Responses are anonymous free text plus confidence and response time. Recruit unfamiliar players before showing them this report. For a meaningful comparison, split the picture trials across participants or counterbalance order to limit learning. Ask for the action they predict before revealing labels. In labeled tasks, record the chosen option, predicted consequence, confirmation expectation and whether active progress is preserved. Code **New game/Continue**, **Archive/Endings/Field replays**, and **Settings-as-audio-only** confusions separately. Record a participant's exact words; do not replace uncertainty with a guessed success. Motion needs a separate counterbalanced pass using the preview's selection sequences; the included static interpretation trials do not validate motion comprehension.

The complete 24-trial test and copyable JSON export were smoke-checked with explicitly synthetic QA responses; that browser session was discarded and is not a participant result. Export presents copyable JSON in the frame, so it also works in a browser sandbox that blocks downloads.
